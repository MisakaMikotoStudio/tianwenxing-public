# 天问星（tianwenxing-public）

> 包名 `dsh-tianwen-star`。本仓库是天问星 DeepSeek Harness 插件的开源部分，DSH 用户通过本仓库安装天问星。

天问星是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）的商务沟通模拟插件，覆盖两类场景：

- **求职面试**：输入公司、JD 和你掌握的补充信息，生成一面、二面、HR 面等多轮面试官，逐轮模拟。
- **商务洽谈**：输入对方公司、面谈对象的姓名和职位、你想谈的合作（例如企业软件定制），生成谈判对象并模拟沟通。

每个场景都按同一流程推进：背景访谈 → 沟通攻略 → 限时模拟 → 角色视角评估 → 复盘。模拟结束后，你能看到两部分记录：一是你和角色的正常对话，二是角色在每一轮没有说出口的真实想法（认可、怀疑、反感……），以及引起这个想法的你的原话，方便定位踩雷和加分的位置。

## 本地 DSH 安装与使用

官网：<https://tianwenxing.yuban.site>

### 1. 准备环境

- DSH `>=0.2.2-rc.4 <0.3.0`（按 DeepSeek Harness 官方文档安装）
- Node.js `>=24.9`

```sh
node -v        # v24.9 及以上
dsh --version  # 0.2.2-rc.4 ~ 0.2.x
```

### 2. 安装插件（二选一）

```sh
# 方式 A：从 Git 直接安装（推荐）
dsh plugin --profile web add github:MisakaMikotoStudio/tianwenxing-public

# 方式 B：克隆到本地后从目录安装（适合要改提示词、评估维度的情况）
git clone https://github.com/MisakaMikotoStudio/tianwenxing-public.git
dsh plugin --profile web add ./tianwenxing-public
```

安装时会自动构建 `lib/`，不需要手动 `pnpm run build`。

### 3. 检查是否装好

```sh
dsh --profile web --dump-config
```

输出中出现 `# == dsh-tianwen-star` 这一层配置即表示插件已加载。

### 4. 启动并开始模拟

```sh
dsh web
```

在输入框下方的模式选择器中选择 **天问星**，然后直接描述你的场景，例如：

- 「下周三我要面试某互联网公司的高级后端工程师，三轮：技术一面、主管二面、HR 面。JD 贴在下面，帮我准备并模拟。」
- 「我要拜访一家制造企业的信息化负责人李总，想谈 MES 系统定制开发，报价 80～120 万，帮我准备一次 30 分钟的首次拜访。」

模拟中可以随时说「暂停一下，我该怎么回答？」「提前结束这一场」「继续下一轮」「回看一面」。

### 5. 更新

重新执行第 2 步的安装命令即可；从本地目录安装的，先在目录里 `git pull` 再执行。

### 常见问题

- **模式选择器里没有天问星**：确认安装和启动用的是同一个 profile（`web`），用 `--dump-config` 检查是否加载，并核对 DSH 与 Node.js 版本。
- **不用 Web 界面**：也能用，教练会以文字形式给出评估报告和内心想法记录，只是没有复盘卡片。

## 使用流程

1. **背景访谈**：天问星先确认场景，再分几轮询问关键信息。面试场景会问 JD、面试流程、你的简历要点、项目、优势、短板和动机；商务场景会问对方的业务现状、面谈对象、合作内容、你方案例、报价区间和底线。需要时它会联网搜索公开信息，并请你确认。
2. **沟通攻略**：针对这家公司和这个人给出攻略，包括对方的考察意图、高频问题和作答要点（STAR）、雷区、要准备的证据、开场和收尾建议、时间分配。
3. **设计模拟**：天问星生成每一场的角色，包括性格、关注点和不会说出口的顾虑（雷区），并按真实场景设定时限：专业面 45～60 分钟，主管面 30～45 分钟，HR 面 20～30 分钟，商务首次拜访 30～45 分钟，高管短会 15～20 分钟。它只告诉你每一场的角色姓名、职位和时限，不剧透角色设定。
4. **模拟**：开始后按真实时间计时。你发出的每条消息都会原样交给角色；角色由一次独立的模型调用扮演，看不到教练的攻略，只按自己的身份、利益和情绪反应。接近时限时角色会主动收尾，超时会结束对话。想暂停求助或提前结束，直接说即可。
5. **评估与复盘**：每场结束后生成评估报告，教练据此复盘。还有下一轮时，下一轮的面试官能看到前几轮的内部反馈，和真实流程一致。

想回看某一场，直接说「回看一面」之类的话即可。

## 复盘卡片

在 Web 界面中，一场模拟结束（或回看）的那一轮回答下方会出现「天问星复盘」卡片，包含三个标签页：

- **沟通记录**：你和角色的完整对话。
- **内心想法**：每一轮角色说了什么、心里想什么、情绪、对你的印象分（0～100），以及这一轮是「加分」「踩雷」还是「中性」，并标出触发反应的原话。
- **评估报告**：总分和等级、结论、成功概率、用时、发言占比、印象变化曲线、维度评分和证据、踩雷时刻（附更好的说法）、加分时刻、改进建议和下一步准备。

模拟进行中，内心想法和评估只保存在 Host，不会发送到浏览器，也不会出现在教练模型的上下文里；一场结束后才解锁。

## 评估体系

评估由角色本人在对话结束后「写内部评估」完成，站在其公司的真实标准上打分，并且必须与模拟时记录的内心想法一致。

- **行为锚定评分（BARS）**：每个维度按 1～5 分打分，每个分值都有行为描述作为锚点，每个分数都必须引用你的原话作为证据。
- **加权总分**：总分 = Σ 权重 ×（得分 − 1）/ 4 ÷ Σ 权重 × 100，由插件确定性计算，不由模型给出；85 分及以上为 A，70 分为 B，55 分为 C，其余为 D。
- **结论等级**：面试为「强烈不推荐 / 不推荐 / 待定 / 推荐通过 / 强烈推荐」，商务为「无合作意向 / 观望 / 有兴趣了解 / 有意推进 / 准备签约」，另附角色估计的成功概率。
- **客观指标**：用时与时限、你的发言占比、平均每次发言字数、印象分的起点、终点、最低点和最高点、加分和踩雷次数，均从对话记录直接计算。

默认维度：

| 面试 | 权重 | 商务洽谈 | 权重 |
| --- | --- | --- | --- |
| 岗位专业能力 | 30 | 需求洞察 | 20 |
| 分析与解决问题 | 20 | 价值主张 | 20 |
| 成果与证据（STAR） | 15 | 专业可信度 | 15 |
| 沟通表达 | 15 | 异议处理 | 15 |
| 动机与文化匹配 | 10 | 沟通与关系 | 15 |
| 职业素养与应变 | 10 | 推进与收尾 | 15 |

教练可以按岗位或轮次自定义维度和权重，例如 HR 面提高「动机与文化匹配」的权重。

## 配置

天问星智能体由 `cordis.patch.yml` 中的 `preset-tianwen-star` 行声明，教练插件是其中 `id: tianwen-coach` 的子行。要修改配置，在 profile 的 `cordis.patch.yml` 中覆盖 `preset-tianwen-star` 行；覆盖会替换整行 `config`，因此要复制完整的 `plugins` 列表再修改。`tianwen-coach` 的可用字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `section` | 内置流程 | 教练的系统提示词段落 |
| `provider`、`model` | 不设置 | 角色和评估调用使用的模型；两者必须同时设置，不设置时复用当前对话的模型 |
| `personaMaxOutputTokens` | 4096 | 角色每轮回复的输出上限（含推理） |
| `personaTimeoutMs` | 120000 | 角色每轮回复的超时 |
| `personaReasoning` | `lowest` | 角色回复的推理强度：`lowest`、`default`、`highest` |
| `evaluationMaxOutputTokens` | 8192 | 评估的输出上限（含推理） |
| `evaluationTimeoutMs` | 300000 | 评估的超时 |
| `evaluationReasoning` | `default` | 评估的推理强度 |
| `jsonRetries` | 1 | 角色或评估输出不是合法 JSON 时的重试次数 |
| `wrapUpRatio` | 0.85 | 用时达到时限的这个比例后，角色开始收尾 |
| `maxExchangesPerStage` | 40 | 单场最多对话轮数，达到后结束 |
| `maxStages` | 6 | 单个模拟最多场数 |
| `maxStageMinutes` | 120 | 单场时限上限（分钟） |

## 费用与模型

每次你对角色说话，都会额外产生一次模型调用（角色回复）；每场结束会再产生一次评估调用。角色调用会带上本场到目前为止的完整对话，因此长时间的模拟会消耗更多 token。角色回复默认使用最低推理强度以降低延迟；如果希望角色更「深思熟虑」，可以把 `personaReasoning` 调高。

## 限制

- 计时按真实时间计算，从角色开场那一刻开始；你思考和打字的时间也计入。
- 复盘卡片只在 Web 界面显示；其他界面中，教练会以文字形式给出相同的评估报告和内心想法记录。
- 模拟数据保存在会话日志中，作为可忽略的插件记录（`plugin:dsh-tianwen-star/record`）；未安装本插件的 DSH 打开该会话时会跳过这些记录。
- 同一会话中同时只能进行一场模拟。

## 开发

```sh
pnpm install
pnpm run typecheck
pnpm run test
pnpm run build
```

目录结构：

- `src/coach.ts`：智能体内的教练插件，注册系统提示词段落、`tianwenStar` 会话投影和 6 个工具（`tianwen_create_simulation`、`tianwen_start_stage`、`tianwen_reply`、`tianwen_end_stage`、`tianwen_review`、`tianwen_status`）。
- `src/prompts.ts`：教练、角色和评估者的提示词。
- `src/rubric.ts`：默认评估维度、结论等级、加权计分和客观指标。
- `src/projection.ts`：从会话日志折叠出模拟状态，并在一场结束前对浏览器隐藏对话和内心想法。
- `src/report.ts`：发给教练模型的评估报告 Markdown。
- `client/client.js`：Web 复盘卡片。
